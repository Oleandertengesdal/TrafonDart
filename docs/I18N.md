# Norwegian & English (i18n)

The UI is fully bilingual. **Every** user-facing string lives in:

```
frontend/src/i18n/locales/nb.json   ← Norwegian bokmål (the default for Norwegian browsers)
frontend/src/i18n/locales/en.json   ← English (fallback)
```

## How the language is chosen

1. The language the user picked in the NO/EN switch (saved in `localStorage`).
2. Otherwise the browser language: `nb`, `nn` and `no` all map to bokmål, and anything else maps to English.
3. After login, the language saved on the account (`users.preferred_locale`) wins, so your choice follows you to the tablet by the board. Switching language while logged in updates the account.

`<html lang>` follows the active language, so screen readers and hyphenation behave correctly.

## Rules for contributors

- **Never hard-code text** in components. Use `const { t } = useTranslation()` and then `t("section.key")`.
- **Add every key to both files.** `npm run i18n:check` (also run in CI) fails if a key is missing on either side or a value is empty.
- **Plurals:** use i18next's `_one` / `_other` suffixes and pass `{ count }`, e.g. `t("match.dartsLeft", { count: 2 })`.
- **Numbers and dates** go through `lib/format.ts`, which uses `Intl` with `nb-NO` or `en-GB`: `85,78` vs `85.78`, `54,3 %` vs `54.3%`, `11. nov. 2026` vs `11 Nov 2026`, and relative times like "for 5 minutter siden" or "5 minutes ago".
- **Backend errors** are never prose. The API returns a code (e.g. `INVITE_EXPIRED`) and the frontend translates it under `errors.<CODE>`. When you add an `ErrorCode` in Java, add both translations.
- **Voice callouts** (`callouts.*`) are spoken with the browser's speech engine in the active language (`nb-NO` / `en-GB`).

## Adding a third language

1. Copy `en.json` to e.g. `nn.json` and translate it.
2. Register it in `src/i18n/index.ts` (`resources`, `supportedLngs`, `LANGUAGES`) and adjust `normalise()`.
3. Extend `check-i18n.mjs` to compare the new file too.
4. Allow the code in the backend: the `preferred_locale` check constraint (new migration) and the `^(nb|en)$` patterns in `UserDtos` / `AuthService`.
