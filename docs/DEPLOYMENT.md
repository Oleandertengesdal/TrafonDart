# Deployment: Vercel + Render + Neon (free tiers)

```
 Browser ──https──► Vercel (React build)
    │                 └─ /api/*  ──rewrite──► Render: Spring Boot (Docker) ──► Neon: PostgreSQL
    └──────wss──────────────────────────────► Render: /ws  (live scores)
```

**Why this split?**

- **Vercel** serves the static React build for free from its CDN. It also proxies `/api` to the backend, so the login cookie stays *first-party*. Safari on iPhone and iPad blocks third-party cookies, and those are the devices most likely to be at the board.
- **Render** runs the Spring Boot Docker image and supports WebSockets. Vercel cannot proxy WebSocket connections, so the browser opens the socket directly against Render, authenticated with a short-lived ticket instead of the cookie.
- **Neon** hosts Postgres. Render's own free Postgres is deleted 30 days after creation. Neon's free plan has no expiry (100 CU-hours of compute and 1 GB of storage per project at the time of writing).

**What to expect from free tiers.** A free Render web service sleeps after 15 minutes without traffic and takes about a minute to wake up. Live socket traffic counts as activity, so it stays awake during a match. The first visit after a quiet period is slow, and the app retries patiently while the server wakes up. A paid Render instance (from about $7/month) removes the sleep. Check the current terms on each provider's pricing page, because free tiers change.

> **Golden rule.** Secrets go into the provider dashboards, never into Git. Every value marked 🔒 below is a secret.

---

## 1. Database on Neon

1. Sign up at neon.com and create a project, for example `trafondart`. Pick a region close to Render's (Frankfurt, `aws-eu-central-1`).
2. Open **Connect** and choose the *pooled* connection. Neon shows a URL like:
   ```
   postgresql://neondb_owner:AbC123…@ep-cool-name-123456-pooler.eu-central-1.aws.neon.tech/neondb?sslmode=require
   ```
3. Split it into the three values the backend expects:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | `jdbc:postgresql://ep-cool-name-123456-pooler.eu-central-1.aws.neon.tech/neondb?sslmode=require` |
   | `DATABASE_USERNAME` | `neondb_owner` |
   | `DATABASE_PASSWORD` 🔒 | `AbC123…` |

   Note the `jdbc:` prefix, and that the user and password are **not** in the URL.

Flyway creates all the tables on the first start-up. You don't need to run any SQL by hand.

## 2. Backend on Render

1. Push this repository to GitHub.
2. In Render: **New → Blueprint**, then select the repo. Render reads `render.yaml` and proposes a web service called **`trafondart-api`** (Docker, free plan, Frankfurt).
3. Fill in the values it asks for:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | from step 1 |
   | `DATABASE_USERNAME` | from step 1 |
   | `DATABASE_PASSWORD` 🔒 | from step 1 |
   | `WS_ALLOWED_ORIGINS` | your Vercel URL, e.g. `https://trafondart.vercel.app` (comma-separate several) |
   | `BOOTSTRAP_ADMIN_USERNAME` | your username, e.g. `oleander` |
   | `BOOTSTRAP_ADMIN_PASSWORD` 🔒 | a strong password, at least 10 characters |
   | `BOOTSTRAP_ADMIN_REAL_NAME` | your real name |

   `JWT_SECRET` 🔒 is generated by Render (`generateValue: true`). `COOKIE_SECURE=true` and `TRUSTED_PROXY_HOPS=2` are preset.
4. Deploy. The first build takes a few minutes. When `https://trafondart-api.onrender.com/actuator/health` returns `{"status":"UP"}`, the backend is ready.
5. **After your first login**, change your password in *Settings*. Then delete `BOOTSTRAP_ADMIN_PASSWORD` in Render. It is only read while the users table is empty.

> If Render gives the service a different URL (for example because the name is taken), use that URL everywhere this guide says `trafondart-api.onrender.com`.

## 3. Frontend on Vercel

1. Edit **`frontend/vercel.json`** and replace `trafondart-api.onrender.com` with your Render host in **two places**:
   - the `/api/:path*` rewrite `destination`
   - `connect-src` in the `Content-Security-Policy` header (`wss://…`)

   Commit and push. These are public URLs, not secrets.
2. In Vercel: **Add New → Project**, then import the repo.
   - **Root Directory:** `frontend`
   - Framework preset: *Vite* (detected). The build command (`npm run build`) and output directory (`dist`) come from `vercel.json`.
3. **Environment Variables** (Production):

   | Variable | Value |
   |---|---|
   | `VITE_WS_URL` | `wss://trafondart-api.onrender.com/ws` |
| `VITE_CONTACT_EMAIL` | *(optional)* where "Report a bug" sends email. Default `adminsjef@uka.no` |

4. Deploy. Open the Vercel URL and log in with your bootstrap admin.
5. If Vercel gave you a different domain than you set in `WS_ALLOWED_ORIGINS`, update that variable in Render and redeploy the backend.

### Custom domain (optional)

Add the domain in Vercel, then add `https://your-domain` to `WS_ALLOWED_ORIGINS` in Render. Nothing else changes, because the API stays behind the same-origin `/api` rewrite.

## 4. Invite the group

**Admin → Invite codes → New invite code.** Choose how many people can use it and how long it is valid. Copy the code or the sign-up link (`/register?code=…`) and share it. The code is shown **once**: only a hash is stored.

### Forgotten passwords

There's no email to set up. An admin opens **Admin → Members → Password link** next to the person, copies the one-time link (valid 24 hours) and sends it to them.

## 5. Updating

Push to `main`. Render and Vercel redeploy automatically, and CI runs tests and a secret scan on every push. Database changes ship as new Flyway migrations (`backend/src/main/resources/db/migration/V2__….sql`). Never edit a migration that has already run in production.

## Troubleshooting

| Symptom | Fix |
|---|---|
| "Can't reach the server" on the first visit | The free Render service is waking up (about 1 minute). The app retries on its own. |
| Live updates don't arrive (the "Reconnecting…" badge stays) | Check that `VITE_WS_URL` is set in Vercel, that the CSP `connect-src` contains the same host, and that `WS_ALLOWED_ORIGINS` in Render matches the exact Vercel origin. |
| Login works locally but not in production | `COOKIE_SECURE` must be `true` (HTTPS), and `/api` must go through the Vercel rewrite, not straight to Render. |
| Backend crashes with `JWT_SECRET is required` | The variable is missing or shorter than 32 bytes. |
| `Schema validation` error on start-up | Someone changed the database by hand. Fix it with a new Flyway migration. |
| Too many `429` responses | The login rate limit was hit (20 per 5 minutes per IP, 6 per 5 minutes per username). Wait, or check that `TRUSTED_PROXY_HOPS=2`. |

## Alternatives

- **Supabase** works instead of Neon. Use its *session pooler* JDBC URL with `sslmode=require`.
- **Railway** can host both backend and database. It is no longer free, but it is simple, and it supports the same Dockerfile.
- **Everything on one VPS:** `docker build backend/` plus Postgres plus any static host for `frontend/dist`. Put a reverse proxy in front that serves `/api` and `/ws` on the same domain, then leave `VITE_WS_URL` empty.
